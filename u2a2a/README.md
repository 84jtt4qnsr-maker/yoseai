# U2A2A Orchestration

Canvas「U2A2A app イメージ」を実装したローカルアプリ。
ユーザー ⇄ Claude Code ⇄ Codex ⇄ Grok のテキストオーケストレーション＋タスクキュー（参加者はトピックごとに選ぶ）。

## 起動

```bash
node u2a2a/server.mjs
```

→ http://127.0.0.1:4742 （ポートは環境変数 `U2A2A_PORT` で変更可）

依存パッケージなし（Node 標準ライブラリのみ）。

## トピック（スレッド）システム

上部タブでトピックを切り替える。各トピックは独立した作業スペースで、
**Claude / Codex それぞれのCLIセッションもトピックごとに別**（文脈が混ざらない）。

- 「＋ 新規スレッド」で作成（そのまま名前入力）。✏で改名、✕で削除（2度押し確認）
- タブは**ドラッグで並べ替え**できる（ブラウザライク）
- メッセージ右クリック →「🌿 ここから分岐」で、その地点までの履歴をコピーした新トピックを作成
  （CLIセッションは非継承・分岐元の要約を引き継いで文脈を再注入。コピーの provenance は不変で、
  🧵詳細とミラー frontmatter に分岐元が記録される）
- 質疑モード・外部セッション同期・タスクはトピック単位。プールは全トピック共有
- 選択中のトピックはブラウザごとに記憶される

### スレッド履歴 = DAS 内の実ファイル

各スレッドの会話は `pool/threads/<名前>-<id>.md` に**自動ミラー**され（会話のたび更新）、
プールのファイルブラウザに「🧵 スレッド履歴」として表示される。

- 選択すると履歴のプレビュー＋「このスレッドを開く」「履歴をコピー」
- 検索でスレッド名も横断ヒット
- 実ファイルなのでエージェントも `u2a2a/pool/threads/…` のパスで**他スレッドの議論を参照できる**
  （例:「threads/設計相談-xxxx.md を読んでレビューして」）
- ミラーは自動生成（編集しても会話には反映されない）。成果物アイテムとしては登録されない

ミラーの構成（v2）:
- frontmatter: topicId・期間・メッセージ数・質疑回数・両エージェントのセッションID（CLI から resume 可能）
- 📌 概要: **自動要約**（12メッセージごと＋質疑終了時に haiku で増分更新。🧵詳細の「要約を更新」で手動も可）
- 📦 成果物: このスレッド由来・言及されたプールファイルの索引
- 🗂 タスク: 状態付きチェックリスト
- 💬 履歴: 時系列・レーン表記。転送/中継の受信側は「↪ 冒頭100文字＋参照」に圧縮（原文は送信元レーンに1回だけ）

## 使い方（Canvas の流れそのまま)

1. **ユーザー帯（上段・緑）** — Claude Code / Codex / 両方 のスレッドへ発言（回答・質問）。
2. **Claude Code 側スレッド（左・橙）／ Codex 側スレッド（右・水色）** — 各アプリでのエージェントの返答・質問を貼り付けて記録。
   - メッセージの「○○へ転送」で A2A（エージェント間）中継。
3. **タスク化** — やり取りから生じたタスクをメッセージからワンクリックでキューへ。
   - 「プロンプトをコピー」で Claude Code アプリ / Codex アプリに貼って作業。
   - 状態: キュー → 作業中 → 結果あり → 完了。
4. **結果を入力** — 各アプリでの作業結果を貼ると、担当エージェントの発言としてスレッドへ再入力される。

## CLI 自動応答

`claude` / `codex` CLI が入っていれば、各スレッドへの発言に対してエージェントが自動で返答する
（スレッドヘッダの「自動応答」でON/OFF、OFF時は従来どおり貼り付け運用）。

- Claude: `claude -p --resume <session>` — 要 `claude` → `/login`
  - `u2a2a/pool/` 限定の Write/Edit と、メディア生成用の `python3` / `ffmpeg` 実行を許可
- Codex: `codex exec` / `codex exec resume <session>` — 要 `codex login`
  - 新セッションは `-s workspace-write -C u2a2a/pool/`（書き込みはプール限定・リポジトリは閲覧のみ）。
    旧セッション（cwd=リポジトリ）は安全のため read-only のまま — スレッドヘッダの ⟳ でリセットすると新方式に切替
- どちらもリポジトリ本体への書き込みは不可（実装作業はタスクキュー経由で各アプリにて）
- 画像（PNG等）・音声（WAV）・動画（MP4, 要ffmpeg）を生成してプールに保存 → スレッドにインライン表示・再生できる
- セッション ID を保存してスレッドの文脈を継続。エラーはヘッダに赤字表示（ホバーで詳細）

## レイアウト

- 右半分: 共有タスクプール — Finder 風ファイルブラウザ（左: ツリー＋検索、右: 選択ファイルの詳細・レビュー）。
  「折りたたむ」でファイルリストだけのレールに収納（行クリックで自動展開＋選択）
  - サブフォルダ対応（▸/▾で開閉）。フォルダをクリックすると「作成先」に指定される
  - ツールバーの 📁+ / 📄+ で新規フォルダ・新規ファイルをその場で作成（ターミナル不要）
  - 持ち込みダイアログ（テキスト/アップロード）も作成先フォルダに保存される
  - 検索中はツリーをフラット化してパス付きで横断表示
  - ドラッグ＆ドロップで移動（ファイル/フォルダ行 → 📁行またはリスト背景=ルート。レビュー履歴は追従）
  - ⧉ボタンまたは Cmd+C でコピー → 「ペースト」または Cmd+V で作成先へ複製（フォルダは再帰）
  - Finder からリストへファイルをドロップするとアップロードになる
- 左半分: ユーザー帯・Claude/Codex スレッド・タスクキュー（未完了があるときだけ自動展開）
- メッセージの操作ボタンはホバーで右上に表示
- 幅 1100px 未満のウィンドウでは自動的に上下配置（プールが下段）に切り替わる

## 表示

メッセージ本文は Markdown をレンダリング表示する（見出し・リスト・コードブロック・
インラインコード・表・引用・太字/斜体/打ち消し・リンク）。内蔵の軽量レンダラーで
外部依存なし、HTML タグはすべてエスケープされるため安全。
メッセージごとの「生表示」ボタンで元テキストと切り替え可能。

## 要約の鮮度（仕様: SPEC-要約鮮度.md）

スレッド要約は「発言 12 件差」と「質疑の決着」で自動更新される。この 2 つのトリガは変えていない。
変えたのは **結果が見えること**。`topic.summaryState` に最後の試行の結果を残す。

```jsonc
{ "phase": "idle" | "running" | "skipped" | "failed",
  "reason": null | "budget-halt" | "budget-cap" | "no-messages" | "already-running" | "cancelled" | "error",
  "detail": "", "ts": 0, "startedTs": null, "trigger": null | "auto" | "manual" | "relay-agreed" }
```

- 成功したら `idle` に戻す。成功の事実は `summaryTs` / `summaryAt` / `summaryLastMsgId` が表す
- 予算停止・上限超過での見送りは、以前は無言で `return` していた。いまは理由が残る
- `GET /api/topics/:id/summary-status` → `{ total, unreflected, threshold, due, state, ... }`
- `POST /api/topics/:id/summarize` → `202 { ok, started, state }`（走行中・見送りは `started: false`）
- **`already-running` は応答にだけ入り、`topic.summaryState` には残さない。** 自動要約の再判定は 30 秒ごとに走るので、
  走行中のトピックは必ずこの分岐に入る。永続化すると「更新中」の表示が開始直後に「見送り」で潰れる

**未反映件数は配送コピーを除いて数える。** 質疑の 1 手番は「応答 1 件 ＋ 配送コピー 参加者-1 件」で保存されるため、
素の件数は 3 名で約 3 倍になる。`lib.unreflectedCount()` が、元発言が同じトピックに居るコピーを落として数える。

`summary-status` の `due`（`unreflected >= 12`）は **表示の強調用で、自動要約の発火条件ではない**。
発火は現行どおり「素の件数 − `summaryAt` >= 12」なので、3 名リレーでは自動要約のほうが先に走る（`due` はほとんど立たない）。

## エージェントの作業文脈サポート

- **変更ファイル通知**: (トピック×エージェント) ごとに前回プロンプト生成時のファイル状態
  （mtime/size・固定監視リストで有界: server.mjs / public/ / U2A2A_RULES.md / topics/<id>/ / runtime/ / ルート*.md）
  を保存し、次回の応答時に「前回以降に変わったファイル: 変更/追加/削除」を注記
  — レビュー中に足元のコードが変わっても、古い行番号のまま話し続けない
- **質疑への途中合流サポート**: 質疑リレーの受信側が初めて合流するとき、
  発端メッセージ・スレッドミラーのパス・現況要約をプロンプトに自動添付

## 質疑モード（エージェント間の自動質疑応答）

送信先で「🗨 質疑（Claude先手／Codex先手）」を選んで発言すると、
先手エージェントの**応答完了を待ってから**相手スレッドへ自動中継し、交互に質疑が進む。

- 上限手数（既定6、送信時に変更可）に達すると自動停止
- エージェントが応答末尾に「【質疑終了】」と書くと合意成立として早期終了
  （ただし相手が一度も発言していない段階の終了宣言は無効 — 最低1往復を保証）
- 進行中は上部バーに残り手数を表示、「質疑を停止」でいつでも中断
- CLI エラー時は安全のため自動停止

## 共有タスクプール（成果物置き場 = アプリ専用 DAS）

実体は **`u2a2a/pool/` フォルダ**（git 管理外）。全アイテムが実ファイルで、
エージェント CLI からは `u2a2a/pool/<name>` のパスでそのまま読める。

- 持ち込み方法:
  - メッセージ／タスク結果の「プールへ」、「＋持ち込み」のテキスト入力（`.md` として保存）
  - 「＋持ち込み」のファイル添付（アップロード）
  - **`u2a2a/pool/` にファイルを置くだけ**（Finder でも、エージェントが自分の CLI セッションから
    書き込んでも、20 秒ごとのスキャンで自動登録される）
- 持ち込むと**相手エージェントが自動レビュー**（ユーザー持ち込みは両エージェント。ダイアログでOFF可、
  フォルダ投入は自動レビューなし＝ボタンで依頼）
- レビューはファイル内容（大きい場合はパス参照）に対して行われ、
  末尾の「【判定】承認 / 条件付き承認 / 差し戻し」をチップ表示
- レビューはスレッドとは別の使い捨てセッションで実行（スレッド文脈を汚さず、並列実行も安全）
- 最終判断はユーザー（承認 / 差し戻しボタン）。再レビュー依頼も各エージェントに個別に可能

### 成果物バージョン履歴（修正操作の履歴）

修正（レビュー後の「修正」ボタン）とレビューの対象がどの版だったかを残す。
実体は **`pool/.versions/<itemId>/`**（`manifest.json` が正本、`v<n>.<ext>` が版のスナップショット）。

- 対象: UTF-8 テキストかつ 256 KiB 以下のファイル。対象外（バイナリ・大きすぎ）は従来どおり
  `.trash/` への修正前バックアップのみで、UI には「履歴対象外」と出る
- 版が切られる契機: 修正前・修正後（CLI が失敗しても内容が変わっていれば `partial` 版として残す）・
  レビュー開始時。直前の版と同じ内容なら版は増えない。外部編集（Finder や別セッション）は版にせず、
  レビュー中に実ファイルが変わった場合にレビューへ `stale` 印を付ける
- 修正の順序: 前版保存 → CLI → 後版保存 → ロック解除 → （履歴保存に成功したときだけ）自動再レビュー。
  前版が保存できなければ修正は実行しない
- 競合: 修正中のレビュー／レビュー中の修正／実行中の削除・移動（対象ファイルとそれを含むフォルダ）は 409。
  別レビュアー同士の同時レビューは可
- レビュー開始時に対象版を保存できない（履歴の保存先の障害・破損）場合、レビューは実行せず
  エラー記録に `historyError` を残す（どの版を見た判定かを保証できないため）。対象外ファイルは従来どおり
- 削除してもアイテムの `.versions/<itemId>/` は残り、`GET /api/pool/<id>/versions` で引き続き参照できる
- API: `GET /api/pool/<id>/versions` → `{ versions, unsupportedReason }`、
  `GET /api/pool/<id>/diff?from=<版id>&to=<版id>` → `{ from, to, diff, truncated }`（from 省略時は直前の版）
- レビュープロンプトには最新版全文に加えて「前版との unified diff」と「前回までの判定」を補助情報として添える
- プレビュー: Markdown はレンダリング、コード/テキストは等幅表示、画像はインライン表示
- 削除はファイルを `pool/.trash/` へ退避（復元可能）

## プールの整理規約（エージェント協議による合意）

- 成果物の既定保存先は **`pool/topics/<topicId>/`**（パスは完全IDで不変。ツリーにはトピックタイトルで表示）。
  Codex の新セッションは cwd がこのフォルダになり、Claude はプロンプトで誘導される
- 中間生成物は `topics/<id>/.work/`（ドット除外で一覧に出ない）。`shared/` はトピック横断用
- `item.topicId`（所属）と `item.file`（所在）は独立 — ファイルを移動しても所属は変わらない
- 直接保存されたファイルの登録時、実行中の run から**作者を正しく帰属**（origin/via:agent）
- **`pool/U2A2A_RULES.md`** = アプリ専用の共通ルール（CLAUDE.md × AGENTS.md）。
  サーバが通常応答・レビュー・修正の全プロンプトに注入する。DAS 内にあるので
  ユーザーはプールから閲覧でき、編集すれば次の実行から反映される（初回起動時に既定内容を自動生成）
- 既存ファイルは移動しない（topicId / origin の情報補完のみ。移動は今後ユーザー判断で）

## 第 3 のエージェント Grok と参加者制

xAI Grok（Grok Build CLI）を加え、**トピックごとに参加者を選ぶ**多者構成にした。既存の 2 名トピックは挙動を変えない。

- **参加者**: 新規スレッド作成・🌿分岐で選ぶ（既定: 自動応答 ON かつ認証済みの全員）。作成後は固定。
  旧トピックは claude / codex の 2 名のまま。Grok は新規参加で、過去には遡らない（途中招待は分岐で代替）
- **Grok の起動**: `grok --prompt-file <一時ファイル> --output-format streaming-json [--resume <id>]`。
  書き込みは `--allow "Edit(u2a2a/pool/**)"`（claude 互換書式）で pool に限定し、`--disallowed-tools spawn_subagent`。
  レビューは `--sandbox read-only`。権限は resume でも毎回渡す（継承されない）。`stopReason: "cancelled"` は
  「権限要求または中断で停止」として赤字表示し、本文・トークン・費用は保持する
- **認証**: `~/.grok/auth.json` の存在＋軽量プローブで判定（起動時と「再確認」）。未認証・確認中の Grok は
  参加者・宛先として選べず、Grok 宛ての送信・依頼は送信前に理由付きで拒否される
- **質疑リレー**: 2 名でも 3 名でも同じ機構。開始時に手番順を固定し、各応答を他の参加者全員へ配送、手番の 1 名だけを起動する。
  `【質疑終了】` は参加者全員が 1 回以上発言した後のみ有効。停止理由（`agreed`／`hops`／`budget`／`error`／`cancelled`／
  `auto-off`／`unauthed`／`manual`）を記録する。終了後に残った配送コピーは「終了した質疑の経緯・返信不要」として次の応答に渡す。
  未読が 10 件を超えた分は捨てず、件数とミラーの参照先をプロンプトに添える
- **レビュー依頼先**: 既定は「作者以外の参加者」（ユーザー持ち込みは参加者全員）。持ち込み時に変更でき、成果物に保存される。
  実行できない相手（未認証・自動応答 OFF・上限）は「未実施」として記録し、レビュー済みに数えない。修正後は実際にレビューした人へ再依頼
- **転送・引き継ぎ**: 3 名時は宛先（`toAgent`）を明示。候補が 1 名なら省略可
- **オフライン指定**: レビュー・修正依頼の `offline: true` で Grok は `--disable-web-search`、他は「検索を使わない」注記。
  検索を使った場合は出典を本文に示す（共通ルール）
- **API**: `POST /api/topics { participants? }`、`POST /api/topics/:id/branch { participants? }`、`POST /api/messages { thread: <参加者> | "both" | "all" }`、
  `POST /api/relay|handoff { toAgent? }`、`POST /api/qa/start { participants? }`、`POST /api/pool { reviewers? }`、
  `POST /api/pool/:id/review|fix { offline? }`、`POST /api/agents/grok/check-auth`。`GET /api/state` に `agentDefs`（名前・色）を同梱

## ローカルプロジェクト登録とトピック紐付け

過去のプロジェクト（GitHub 未使用のローカルフォルダを含む）を登録し、トピック単位で「対象」として紐付ける。
両エージェントは同じ対象を読んで相談・改修案（成果物）を作る。GitHub からの取り込みは次フェーズ。

- 登録: ヘッダの **📁 プロジェクト**（または `POST /api/projects { path, name? }`）。パスは実体パスへ正規化し、
  ディレクトリであること・**プール（`u2a2a/pool/`）配下でないこと**を確認する。`.git` があれば `kind: "git"`
- 紐付け: 新規スレッド作成時・🌿分岐時に選ぶか、未実行のトピックで変更する。**一度でも実行したトピックは変更不可**
  （`topic.projectLocked`。外部セッション同期で取り込んだエージェント発言も「実行」に数える）。
  別プロジェクトで続けたいときは分岐で新しいトピックを作る
- 読み取りのみ: 書き込み範囲は変えない（Claude は `Edit(u2a2a/pool/**)`、Codex は `-C pool`）。
  Claude には `--add-dir <path>` で読み取りだけを許可し、修正実行も `acceptEdits` ではなく同じ規則で動かす
- プロンプト: 「対象プロジェクトは「名前」（パス、閲覧のみ）。Git: ブランチ@HEAD、未コミット変更 N 件」を注入。
  セッション初回のみ README 冒頭＋直下エントリ名の概要（4,000 文字まで）を添える。未紐付けは従来どおり Kometa リポジトリ
- Git 情報は保存せず都度取得（`execFile("git", …)`、shell なし、3 秒タイムアウト）。取れなければ「確認不可」と表示し、実行は止めない
- 紐付け先が **存在しない・読めない・登録が解決できない** ときは、その対象を必要とする応答・レビュー・修正を止めて理由を残す
  （Kometa へ自動で戻さない）
- 成果物には登録時のトピックの `projectId` を写し、レビュー・修正はそれを使う。参照されている登録は削除できない（409）
- API: `GET/POST /api/projects`、`PATCH/DELETE /api/projects/:id`、`GET /api/projects/:id/probe`、
  `POST /api/topics { title?, projectId? }`、`PATCH /api/topics/:id { projectId }`（実行済みは 409）、
  `POST /api/topics/:id/branch { messageId, projectId? }`

## 外部セッション同期

各スレッドの実体は通常の CLI セッションなので、デスクトップ版 Claude Code や
ターミナル（`claude --resume <id>` / `codex resume <id>`）で同じスレッドを続けられる。
外部でやり取りした分はセッション記録ファイルの増分から検出し、
「外部セッションから同期」ラベル（破線枠）でスレッドに取り込まれる。

- チェックは 30 秒ごと＋各自動応答の直前
- 同期されたメッセージは自動応答のトリガーにはならない（外で完結した会話に二重返答しない）

## コンテキストメニュー

右クリック（または メッセージの ⋯ ボタン / Shift+F10）で対象に応じた操作メニューを表示。
対象外の場所ではブラウザ標準メニューを維持する。

- メッセージ: コピー／引用して入力欄へ／タスク化／🤝相手へ引き継ぎ／🌿ここから分岐
  - 引き継ぎ（handoff）は転送と違い「バトンを渡す」操作。受け手には
    「ここから先をあなたが引き継いで進めてください（全文脈はスレッドミラー参照可）」という
    依頼フレームでプロンプトが届き、相手が作業を引き取って続きを進める
- プールのファイル: ⧉コピー／📋貼り付け／パスを入力欄へ挿入／レビュー依頼（Claude・Codex）
- プールのフォルダ: フォルダごとコピー／このフォルダへ貼り付け／パス挿入
- トピック（タブ・🧵行）: 要約を更新／履歴をコピー／名前を変更／質疑リレー停止
- 実行中（実況ボックス）: ⏹ 実行を中断

## 実行制御（キャンセル・上限・ヘルス）

- 実行中の応答は実況ボックスの **⏹ 停止** で中断（SIGTERM→3秒→SIGKILL・プロセスグループ停止）。
  中断したセッションは次回新セッション＋要約再注入で継続し、**↩ 中断分を再開** で明示的に元セッションへ戻れる
- ヘッダの **⚙ 上限** で予算設定: トピック別コスト上限（USD実測）／1日の実行回数／累計実行時間（走行中込み）。
  到達すると自動応答・質疑を全停止し赤バナーで理由を明示、「解除して再開」で復帰
- 各応答の下に **⏱時間・トークン・$コスト** のフッター（メタは status/usage/billing に正規化）
- ヘッダの **🩺** で運用イベント（永続化・同期・要約などの失敗ログ）とストレージ計測
  （state.json サイズ・保存時間）を確認できる

## フロービュー（グラフ導出）

スレッド 3 列の代わりに「最初と最後が見えて、途中は束」の進行を見せる表示（仕様: `pool/topics/9a299f1bac1a09fb/SPEC-フロービュー.md`）。
扱う情報は `state` のまま。導出は `public/flow-graph.js` の純関数 `buildFlowGraph(publicState の一部, options)` で、
ブラウザ（`<script type="module">`）と Node（`lib.mjs` が再 export、`test/flow.test.mjs`）が同じファイルを読む。サーバは変更しない。

- 束（エピソード）: ユーザー発言（`ingress:"ui"`・`delivery:"direct"`）を起点に 1 束。`all` 送信はレーンごとに別 ID なので、同文・別レーン・先頭から 50ms 以内を「推定の送信束」（`inferred`）にまとめる。質疑開始（`relay.startMessageId`）は単独束
- ノード: `send` / `reply` / `replies`（同一束・同一著者 2 件以上）/ `relay`（質疑 1 本を `relayId` で 1 枚）/ `unrelayed`（`staleRelayId`）/ `sync`（外部同期。`ingress:"cli-sync"` はユーザー発言も含む）/ `system`（blocked・cancelled）/ `artifact` / `task` / `pending`（実行中）
- エッジ: 明示 ID（`source.messageId`・`fromMessageId`・`taskId`・`copiedFromMessageId`・`branchedFrom`）だけ実線。ユーザー発言→応答はレーン＋時刻の推定で破線（入力集合の復元は約束しない）。配送先の無い転送・引き継ぎ・未中継は終端マーク
- `membership`（元メッセージ ID → 所属カード key）で、束ねても成果物・分岐の接続先を失わない。分岐先ではコピーが新 ID を持つため、`copiedFromMessageId` で親側の ID を読み替える
- 折りたたみは既定値だけ返す（先頭・末尾 2 束・実行中・分岐点を含む束は開く）。1 行の件数は応答・成果物・タスク・外部同期・リレー
- fixture: `test/fixtures/flow-*.json`（入力→出力の組。描画側の先行実装用）。更新は `FLOW_FIXTURES_UPDATE=1 node --test test/flow.test.mjs`
